# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Robot *description* packages (URDF + meshes) for the BD-X droid, plus a MuJoCo
simulation pipeline for the bipedal legs.

## Commands

```bash
# One-time: create the .venv and install mujoco (pyproject.toml; uv, non-packaged project)
uv sync

# Regenerate the MuJoCo robot model from the URDF. Runs from anywhere — the script
# chdir's to its own directory. Re-run after ANY edit to the bdx.urdf

uv run python build_mujoco_xml.py

# Headless check that the assembled model compiles (load via world.xml — the robot
# include dreambo_asymmetry.xml is a fragment and can't be loaded standalone).
uv run python -c "import mujoco; mujoco.MjModel.from_xml_path('world.xml')"

# Interactive viewer (needs a display)
uv run python -m mujoco.viewer --mjcf=world.xml
```

## MuJoCo model architecture

The model is split across `<mujocoinclude>` fragments stitched together by a
top-level world:

- **`world.xml`** — the only real `<mujoco>` root. Pulls in `scene.xml` +
  `dependencies.xml`, drops the robot include inside `<worldbody>`, and defines the
  12 `<motor>` actuators and the `<sensor>` block (per-joint actuatorpos/vel/frc +
  IMU sensors on the `imu` site). This is where actuators/sensors live — NOT in the
  robot body include.
- **`dreambo_asymmetry.xml`** — **generated** by `build_mujoco_xml.py`. A
  `<mujocoinclude>` holding only the robot body tree. **Do not hand-edit**; change
  the URDF (or the script) and regenerate.
- **`dependencies.xml`** — `<compiler>` (meshdir `../meshes/`) + the `<mesh>` asset
  list. Mesh `name=` here must match the `mesh=` refs in `dreambo_asymmetry.xml`.
- **`scene.xml`** — `<option>`, visual settings, floor geom, lights.
- **`world_terrain.xml`** — a **self-contained** terrain-training world. Same dreambo
  include + actuators + sensors as `world.xml`, but it does NOT include `scene.xml`:
  it pulls in only `dependencies.xml` and defines its own `<option>`/`<visual>`/lights
  plus a flat ground plane at **`z=0`** (dreambo's original training-floor height —
  `scene.xml`'s `z=-0.505` floor is sized for the taller reference robot and would
  leave dreambo floating ~0.4 m). On top of the ground it lays a progressive obstacle
  course along +X: rough ground → washboard bumps → a hill → small stairs → stepping
  platforms → step-over barriers. All obstacles are additive boxes on the infinite
  ground plane, so stepping off one is a small drop, never a fall into a void. The
  obstacle geometry is generated by a one-off helper script (not committed); to tweak
  the course, edit the `<geom>` list directly.

Because the includes use relative paths, always load/compile via the file that
references them (e.g. `world.xml`) from a cwd where `../meshes/` resolves.
